# Sanitaryware CRM QA Report

Date: 2026-10-11
Target: `http://127.0.0.1:5173`
Mode: gstack QA report-only, browser/manual plus available automated checks
Framework: React/Vite SPA with Spring Boot API

## Executive summary

The public browser surface loads correctly. Login and registration forms expose the expected controls, native required-field validation works, the registration link works, and a protected dashboard route redirects unauthenticated users back to `/login`.

Full authenticated workflow coverage was blocked because the test browser had no authenticated session and the QA policy does not permit typing passwords or tokens. Endpoint and Playwright execution was also blocked by the local sandbox permissions after the backend was launched. The backend log confirms the packaged JAR started on port 8081, but it validated only migrations through V8, so the JAR is stale compared with the working tree's new V9 migration.

## Manual browser coverage

### Login page

- Loaded successfully at `/login`.
- Brand panel, heading, username field, password field, sign-in button, and registration link were visible.
- Clicking `Sign In` with empty fields produced native browser validation: `Please fill out this field.`
- No authenticated session was available for a successful login test.

### Registration page

- Loaded successfully at `/register`.
- Full name, username, email, phone, password, register button, and sign-in link were visible.
- Clicking `Register` with empty fields produced native browser validation.
- Filling non-secret test values in the public fields and submitting without a password correctly focused the password field and showed required-field validation.
- No account was created because entering a password was intentionally not performed.

### Protected route

- Navigating directly to `/dashboard` while unauthenticated redirected to `/login`.
- This confirms the public route guard is active for the dashboard.

## Findings

### QA-001: Authenticated workflows could not be verified

Severity: High
Category: Coverage blocker

The browser reached the login wall, but no authenticated browser session was available. As a result, dashboard, products, customers, quotations, orders, payments, purchasing, reports, settings, audit logs, role restrictions, file uploads, downloads, and logout could not be exercised manually.

This is a test-environment limitation, not a confirmed application defect.

### QA-002: Test server artifact is stale relative to the working tree

Severity: High
Category: Build/release verification

The running `backend/target/crm-backend-1.0.0.jar` reported Flyway validation through V8, while the working tree contains `V9__Make_Initial_Admin_Bootstrap_Atomic.sql`. Current source behavior was therefore not fully represented by the running artifact.

### QA-003: Endpoint and Playwright suites are blocked by environment permissions

Severity: High
Category: Test infrastructure

The normal test process could not reach the locally bound backend and Playwright failed while removing `automation-tests/test-results` with `EPERM`. Elevated execution was requested but rejected, so the suites could not be rerun with the required permissions.

### QA-004: Browser test surface is limited to public flows

Severity: Medium
Category: Coverage

The public login and registration flows were testable, but every business workflow requires an authenticated user. A complete button-by-button audit requires a user-provided authenticated browser session or a permitted QA credential flow.

## Health score

No numeric gstack health score is assigned. The weighted score requires authenticated page coverage, console inspection after interactions, link checks, and full workflow evidence. Those categories were not fully testable in this environment.
